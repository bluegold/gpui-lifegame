# GPUI Conway's Game of Life

GPUI上で Conway's Game of Life を動かすための設計案です。疎な盤面をチャンク単位で管理し、表示範囲と変更箇所に応じて処理量を抑えます。詳しい設計は [DESIGN.md](./DESIGN.md) を参照してください。

## 設計の概要

盤面は 64 x 64 セルのチャンクに分割し、生存セルを含むチャンクだけを保持します。世代更新では、そのチャンクと隣接チャンクを計算対象にします。描画時はビューポート内のチャンクごとに `TileView` を作り、カスタム `Element` で生存セルを描画します。

カメラは盤面座標と画面座標を変換し、パンとズームに応じて表示範囲を選びます。ズームアウト時はセルを個別に描く代わりに、ブロックやチャンク単位で集約して表示する計画です。世代更新と描画の頻度は分け、最後に描画した状態から変化したチャンクだけを更新します。

## 初期段階の対象外

初期段階では、Hashlife、GPUによる世代計算、無限精度座標、RLEなど外部形式への完全対応、巨大パターンの永続化を扱いません。OSやGPUに対する部分描画の制御も対象外です。

## 操作

初期UIでは、Start / Pause、Step、Clear、Randomizeとシミュレーション速度の調整を提供します。マウスクリックやドラッグでセルを編集できます。ドラッグで盤面をパンし、ホイールやジェスチャーでズームします。

## ディレクトリ構成案

```text
src/
├── main.rs       # GPUI の起動
├── app.rs        # アプリケーションの状態
├── world.rs      # 疎な盤面データ
├── chunk.rs      # 64 x 64 セルのビット表現
├── simulation.rs # 世代更新
├── viewport.rs   # 表示範囲と UI の調整
├── tile.rs       # カスタム描画
└── camera.rs     # 座標変換
```

## 実装順序

まず `Chunk` と `World` を実装し、ライフゲームのルール、チャンク境界、負の座標をテストします。次にカメラ、盤面の描画、セル編集、パンとズームを実装します。その後、Step、Start / Pause、差分管理、シミュレーションと描画の分離へ進みます。詳細度の制御とビット並列化は基本動作を検証してから扱います。

## テスト方針

シミュレーションのロジックはGPUIから分離し、Rustのユニットテストで検証します。still life、oscillator、gliderに加え、チャンクの辺や角をまたぐパターン、空チャンクの削除、負の座標を確認します。座標変換と表示対象チャンクの選択もテストします。

## 性能方針

盤面全体の走査やセルごとの UI 要素生成を避け、計算対象と表示対象を必要な範囲に絞ります。詳細なデータ構造、差分管理、性能指標、受け入れ条件は [設計書](./DESIGN.md) に記載しています。
