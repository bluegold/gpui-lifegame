# GPUI Conway's Game of Life

Rust と GPUI で作った Conway's Game of Life のデスクトップアプリです。盤面は 64 x 64 セルのチャンクに分けて管理します。

## 起動

Rust の stable toolchain と、GPUI の実行に必要な OS の描画・ウィンドウ関連ライブラリを用意します。

```bash
cargo run --locked --features desktop --bin gpui-lifegame
```

初期状態にはグライダーが配置されています。リリースビルドは次のコマンドで作成できます。

```bash
cargo build --locked --release --features desktop --bin gpui-lifegame
```

## 操作

| 操作 | 動作 |
| --- | --- |
| Start / Pause | 自動実行を開始・停止 |
| Step | 1 世代進める |
| Clear | 盤面と世代数をリセット |
| Randomize | 表示中心付近の 64 x 64 セルをランダムに初期化 |
| − / + | 実行速度を 5 世代/秒ずつ変更（1〜120 世代/秒） |
| 左クリック / 左ドラッグ | セルを反転し、ドラッグ中は開始時の状態で連続して描画 |
| 中ボタンドラッグ | 盤面をパン |
| ホイール | カーソル位置を基準にズーム |
| CSV | 計測データの保存先を選択して CSV に出力 |

画面上部には世代数、実行速度、UI FPS、シミュレーション時間、候補チャンク数、表示チャンク数、タイル数、描画項目数などが表示されます。CSV には経過時間、カメラ位置、セルの表示サイズ、シミュレーションと描画の時間、チャンク数など、最大 10,000 件の計測サンプルを出力します。

## 実装の概要

- `World` は生存セルのあるチャンクだけを保持し、空になったチャンクを削除します。セル座標には `i64` を使います。
- 世代更新では生存チャンクとその周囲を計算対象にします。64 セル分の近傍数をビット演算で並列に数え、変更されたチャンクを記録します。
- カメラはパンと 0.0625〜128 ピクセル/セルのズームに対応します。表示タイル数が上限を超えると、複数チャンクをまとめて表示します。ズームアウト時はセル、小ブロック、チャンクの順に生存密度を集約して描きます。
- GPUI Canvas でタイルを描画します。内容が変わっていない表示タイルは再利用します。

## ソース構成

```text
src/
├── main.rs       # デスクトップアプリのエントリーポイント
├── app.rs        # UI、操作、シミュレーション進行、計測 CSV
├── camera.rs     # 盤面と画面の座標変換、パン、ズーム
├── chunk.rs      # 64 x 64 セルのビット表現
├── coords.rs     # セル・チャンク座標の変換
├── simulation.rs # 世代更新と差分・統計
├── tile_view.rs  # GPUI Canvas によるタイル描画
├── viewport.rs   # 表示範囲と描画タイルの計画
└── world.rs      # 疎な盤面データ
```

盤面、座標、シミュレーション、表示範囲のロジックは GPUI に依存しません。デスクトップ UI と描画モジュールは `desktop` feature で有効になります。

## テストと CI

ユニットテストは次で実行できます。

```bash
cargo test --locked --features desktop
```

GitHub Actions は Pull Request とブランチへの push でテストと Linux x86_64 向けリリースビルドを実行します。`v*` タグを push すると、タグ名と `Cargo.toml` のバージョンが一致することを確認したうえで、実行ファイルの tar.gz と SHA-256 ファイルを GitHub Release に登録します。リリース前に `Cargo.toml` のバージョンを更新し、同じ番号に `v` を付けたタグを push してください。

```bash
git tag v0.1.1
git push origin v0.1.1
```
